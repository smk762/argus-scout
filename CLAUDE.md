# CLAUDE.md — argus-scout

Guidance for AI agents working in this repo. Human-facing usage lives in [README.md](README.md); this file is the orientation an agent needs to change code safely.

> Scaffolded from [`argus-pkg-template`](https://github.com/smk762/argus-pkg-template). Flesh out **Must never happen**, **Layout** and **Gotchas** below as the code grows — the suite conventions are already correct and shared.

## What this is

Homelab intelligence for the Argus suite: reads your telemetry, reasons about it, and reports back with briefings and recommendations it never acts on.

**Advisory only.** Scout reads (Prometheus via PromQL, status events sent to it) and reports (briefings, recommendations). It never executes, deploys or dispatches anything, and never scrapes or connects to the hosts it reports on. A standing approval may move a recommendation to `approved`; nothing moves it further except a person.

Development runs in phases tracked by the epic issue in this repo. The policy core was ported from a private deployment (mithrandir) with its globals removed: every module takes its config explicitly.

Shared code — the target taxonomy, wire-schema versioning, and the local/remote model contract — lives in **argus-cortex**; import it rather than re-implementing.

## Layout

`src/argus_scout/` — the package. Key modules:

- `__init__.py` — version shim (`__version__` from `hatch-vcs`).
- `cli.py` — Typer app; entry point `argus-scout` (`[project.scripts]`). `init` writes a starter config; `check` validates config files (`check config` covers scout.yaml, every file it names and every source entry); `poll --config [--source] [--ingest]` (one poll, dry run by default); `analyze --config [--dry-run]` (one signal evaluation + engine cycle; `--dry-run` works on `SqliteStore.copy_of`); `tariff now`; `serve --config`.
- `config.py` — `ScoutConfig`, the one config file (`scout.yaml`): `files`, `store`, `sources` (built-in kinds `webhook` / `json_poll` validated here; any other kind loads as `PluginSource`, keys kept, and is validated by its plugin's `config_model` in `sources.build_sources`; plugin models subclass `SourceSettings`), `schedule`, `services`, `server`. Pydantic v2, `extra="forbid"`, frozen. `load_config` resolves relative paths against the config's directory, loads `.env` beside it (never overriding the real env) and raises `ConfigError` on anything invalid. Secrets are env-var *names* (`token_env`, `auth_env`, `api_key_env`), read with `resolve_secret` as `SecretStr`.
- `severity.py` — `Severity` (info < notice < warning < critical), `coerce_severity`, `rank`.
- `events.py` — `StatusEvent`, the envelope every source sends; `fingerprint` (content identity) and `group_duplicates`.
- `heartbeat.py` — `HeartbeatPolicy` (defaults + YAML overrides, `origin` per key), `PolicyFile` (mtime reload), the `broadcast_gate` / `report_gate` / `voice_gate` chain and `explain()`, `reannounce_due`.
- `recommendations.py` — `Recommendation` (`to_dict` / `from_dict`; `key`, `expires_at`, `last_seen_at`, `retired_reason` default empty so older stored rows load), `Status`, `TRANSITIONS` (`proposed → retired` withdraws a stale proposal); `approve()` / `reject()` / `retire()` take an optional `now` and keep the audit trail.
- `prometheus.py` — `PrometheusClient(base_url, fetcher=)`: read-only `query` / `query_range` via `argus_cortex.net.afetch`, configured host the only one allowlisted, no redirects. Typed results (`Sample`, `Series`) and errors (`PrometheusUnavailable`, `PrometheusQueryError`, `PrometheusResponseError`, all `PrometheusError`): a failure is unknown, never an empty result.
- `signals.py` — declarative rules (`SignalRule`: `name`, `query`, `op`, `threshold`, `for`, `severity`, `escalate`, `labels_key`, `labels`, `rejection_ttl`, `expires_after`, `recommendation`). `parse_rules` / `load_signal_rules` skip bad rules with an error; `SignalRulesFile` (mtime reload). `render` / `template_fields`: allowlisted plain-name placeholders, precision-only specs on numbers, no `format_map`. `SignalState` (pending `for` clocks, persisted via the store). `async evaluate(rules, client, now, state=)` → `Evaluation` (a `list[SignalHit]` plus `evaluated` / `unknown` / `pending`); `dedup_key`; `make_hit` and `Evaluation.merge` are the seam for other evaluators (tariff rules).
- `engine.py` — `RecommendationEngine(store, approvals, clock=, clear_grace=1h, default_ttl=7d)`. `run_cycle(hits)` → `CycleReport` (new / refreshed / auto_approved / retired / suppressed / unknown): dedup by key onto an open recommendation, rejection memory (suppressed unless severity escalates past the rejected one, or the rule's `rejection_ttl` has passed), standing approvals on `proposed` (guardrails win), proposed-only expiry (cleared past grace for an evaluated rule, or past `expires_at`; unknown never clears). `recent_rejections(limit)` → `Rejection`.
- `approvals.py` — `StandingApprovals` (file rules + runtime rules, optionally persisted via a `RuntimeRuleStore`), `guardrail_block`, `briefing_lines`.
- `budget.py` — `DailyBudget` (per-kind daily caps, optional persisted state, `on_change` hook for gauges), `ManualOriginMiddleware`.
- `tariff.py` — `Tariff` / `Plan` / `TariffPeriod` / `TariffTier`; `current_period`, `next_period_change`, `coverage_gaps`, `tiered_cost`; `TariffFile` (mtime reload, `None` on a bad file). Rates are in the currency's minor unit.
- `scheduler.py` — asyncio `Scheduler(store, clock=, sleep=)`: `add(name, async_fn, trigger, retry_delay=)`, `tick(wait=)`, `run_now`, `run_forever`, `start()` / `stop()`. Triggers: `Every(seconds)` and `DailyAt(time, tz, grace=)` (per-local-date slots, so DST fires once; a missed slot runs late only within `grace`, never a backlog). Last successful run per job persists in the store's `job_runs`, so restarts neither repeat nor reset. A raising job is logged, counted and retried after `retry_delay`; a job never overlaps itself. Clock and sleep are injected: tests never sleep.
- `cycles.py` — the jobs: `StatusCycle(store, policy_file, inbox=)` (reloads the heartbeat policy every run, so a bad edit degrades to defaults; skips rest hours; decides each `Inbox.open_grouped()` group with `explain`; delivery comes later), `AnalysisCycle(store, rules=, client=, approvals=)` (reloads the signals file, evaluates, runs the engine; skips without Prometheus or rules, and on an unparseable file; an outage makes rules unknown and never raises), `BriefingJob(kind)` (records runs until narrative), `PollJob(bound_source, inbox)` (one per polling source, ingests via `Inbox.ingest`). `register_jobs(scheduler, config, store, policy_file)` names them `status`, `analysis`, `briefing:<kind>`, `poll:<source>`; the name keys the persisted bookkeeping.
- `store/` — persistence (stdlib `sqlite3`, no ORM). `base.py`: the `Store` Protocol plus `InboxEntry`, `Transition`, `Report`, `JobRun`. `sqlite.py`: `SqliteStore(path)` (`":memory:"` for tests) — status events keyed by `(source, event_id)` with first/last seen, ack, fingerprint index and announce state; recommendations with a `recommendation_transitions` audit table; runtime standing-approval rules (`StandingApprovals(store=...)` loads and writes through; file rules never stored); reports; scheduler `job_runs` (migration 2); recommendation `key` column + index (migration 3; `recommendations_by_key`, `recent_rejections`); signal rules' pending state `signal_pending` (migration 4); `copy_of(path)` for dry runs; scrape-time counts for `/metrics` (`recommendation_counts`, `approval_counts`, `open_event_counts`); `prune()`. Migrations are ordered scripts in `MIGRATIONS`, tracked by `PRAGMA user_version` and applied on open: append, never edit a shipped one. One connection behind an `RLock` (shared by the app and scheduler threads), WAL, foreign keys on. Datetimes are UTC ISO text with fixed microseconds, so they compare as strings.
- `inbox.py` — `Inbox(store, clock=)`: `ingest()` → `IngestResult` (`Outcome`: new / duplicate / escalated / updated / refreshed), `ack()`, `open()`, `open_grouped()` (→ `EventGroup` by fingerprint, which includes the source). `parse_envelope` is the strict validator for envelopes arriving as data (`InvalidEvent` names the field); `normalise` clips, coerces and strips bookkeeping. Records only: never moves a recommendation or sends anything.
- `sources/` — status sources as plugins. `base.py`: `Source` / `PollingSource` (`async poll`) / `PushSource` (`parse`, `authorize`) protocols, `SourceError`, `SourceAuthError(status)`. `registry.py`: kinds from the `argus_scout.sources` entry-point group (built-ins always present and can't be overridden); `build_sources(config)` → `Sources` (bound sources + per-entry errors). `webhook.py`: `parse_webhook`, `check_token` (argus-cortex `auth.check_bearer`, fails closed), no route. `json_poll.py`: `poll_once` via `argus_cortex.net.afetch`, `map_response` (dotted `items` / `fields`, stable derived ids).
- `server/app.py` — `create_app(config, *, store=, budget=, inbox=, sources=, clock=, sleep=, run_scheduler=)` (`[server]` extra). The lifespan builds a `Runtime` (store, policy file, inbox, tariff, usage caps persisted beside the store as `usage.json`, scheduler, metrics registry) on `app.state.runtime`, starts the scheduler and stops it on shutdown; building the app opens nothing. `Runtime.sources` holds the bound sources. Routes: `/health`, `/metrics` (always open) and the API (`server/routes/`). `install_guards` + `include_routes` are the only API wiring here.
- `server/guards.py` — the security boundary. `install_guards(app, server)`: `WriteGuard(cross_site_refuse(allowed_origins))`, plus `WriteGuard(constant_refuse)` outermost when `read_only` (the default). `write_auth(server)` = `argus_cortex.auth.bearer(token_env)` (no `token_env` → always 503); `source_auth(server)` for the push route = the source plugin's `authorize` (webhook: its own `token_env`, else the server token); `read_auth(server)` when `server.read_auth`. Auth dependencies carry `AUTH_MARK`; `iter_routes(app)` flattens FastAPI 0.16x's lazily included routers and `unguarded_routes(app)` reports any write route without guards. `read_bounded` / `read_json` (caps `EVENTS_MAX_BYTES` 256 KiB, `ACTION_MAX_BYTES` 8 KiB): write routes take `Request` and read the body after auth.
- `server/routes/` — `events.py` (`POST /api/events/{source}`, all-or-nothing batch, per-event inbox outcome; `POST /api/events/{source}/{event_id}/ack`; `GET /api/events` grouped), `recommendations.py` (manual `approve` / `reject` with `{by, reason}`, proposed only, 409 otherwise, recorded through `store.save_recommendation`; `GET /api/recommendations?status=&limit=`, `GET /api/recommendations/{id}` with history; no route past `approved`), `reads.py` (`GET /api/reports/latest?kind=`, `GET /api/policy/explain`, `GET /wall` as text/plain with control characters stripped), `models.py` (request bodies, unknown keys refused).
- `server/deps.py` — `get_runtime(conn)` (503 when the app isn't running).
- `server/metrics.py` — `ScoutCollector`, a custom collector on its own `CollectorRegistry` (never the global one) that reads the store, usage caps, tariff file and scheduler at scrape time, so values survive restarts. Families: `scout_usage_used` / `scout_usage_limit{kind}`, `scout_tariff_loaded`, `scout_tariff_period{plan,period}`, `scout_tariff_rate{plan,period,currency,unit}`, `scout_tariff_next_change_seconds{next_period}`, `scout_recommendations{status}`, `scout_approvals_total{source}`, `scout_inbox_open_events{severity}`, `scout_job_runs_total` / `scout_job_errors_total` / `scout_job_last_success_timestamp_seconds` / `scout_job_running{job}`.
- `examples/` (repo root) — commented config for each policy file scout reads; tests load them, so they must stay valid.
- `src/argus_scout/examples/` — packaged templates `argus-scout init` writes (`scout.yaml`, `env.example` → `.env.example`); tests validate them.

## Conventions & gotchas

- **Versioning is git-tag-derived** (`hatch-vcs`). Never hand-edit a version; `src/argus_scout/_version.py` is generated (gitignored). Tag `vX.Y.Z` to release.
- **`src/` layout, `py.typed`, Pydantic v2, `structlog`.** Ruff line-length 120; keep it clean (`make lint`) before committing.
- **Any endpoint that does something is a boundary.** There's no auth by default — treat reaching the port as host access. Gate state-changing routes behind the shared read-only / origin guards, and fence any caller-supplied path under a configured root.
- Wire schemas (if any) are checked in and verified in CI — regenerate and commit when the types change, don't let the committed copy drift.

## Branches

`dev` is the default branch and the base for every PR. Cut feature branches from `origin/dev` and bring them up to date by merging `origin/dev`, never `main`. Never push work to `main` or open a PR against it, except the release PR from `dev`: `main` must never be ahead of `dev`, with one exception. A release fast-forwards `main` to a `dev` commit that passed CI (`git push origin origin/dev:main`), then tags it. If `main` is protected, the release is a reviewed PR from `dev` into `main`, and merging it leaves a merge commit on `main` alone. That merge commit is the one exception to the rule: it leaves `main` one commit ahead of `dev` with an identical tree. Leave it there and don't merge `main` back into `dev`. Anything else on `main` that `dev` lacks is a mistake (`git diff origin/dev origin/main` must be empty). Once `main` carries such a commit it can't be fast-forwarded, so later releases are PRs too.

## CI / release

CI runs via the shared [`argus-ci`](https://github.com/smk762/argus-ci) reusable workflow. `docs.yml` runs its `docs-check` on every push: published docs (`README.md`, `docs/**/*.md`) must hold no private IPs, home/server paths or personal emails (use placeholders like `<GPU_HOST>`), and `docs/cli.md` must match the CLI — run `make docs` after changing a command. Release publishes to PyPI (OIDC trusted publishing) + GHCR on `v*` tags. Run `copier update` to pull template (CI/release/tooling) changes.
